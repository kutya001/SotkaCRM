## 2. Архитектурный базис и стек технологий

- **Фреймворк:** Next.js (App Router, Server Components + Server Actions / Route Handlers).
- **Frontend & Стилизация:** React, Next.js, Tailwind CSS, Lucide React (контурные линейные иконки, толщина 1.75-2.0, **строго без эмодзи**).
- **База данных & Backend-as-a-Service:** PostgreSQL 15+ в инфраструктуре Supabase (Supabase Auth, Row Level Security, Triggers, Functions).
- **Интеграция с внешней платформой:** Серверный прокси-роут `/api/sync/sotka` с авторизацией по токену сессии и проверкой роли `admin`. Прямой доступ клиентов к Sotka API запрещен.
- **Типизация:** Строгая генерация типов `types/database.types.ts` на основе DDL-схемы.

## 4. Инварианты бизнес-логики и целостности данных

1. **Неизменяемость реестра лидов:**
   - Триггер `prevent_lead_delete` (`trg_lock_lead_delete`) на таблице `leads` пресекает операцию `DELETE` на уровне ядра СУБД с выбросом `EXCEPTION`.
   - Исключение из воронки оформляется исключительно статусом `status = 'Отмена'`.
   - В клиентском коде и серверных обработчиках метод `supabase.from('leads').delete()` запрещен.
2. **Жизненный цикл сделки (Воронка лидов):**
   - Строгий `lead_status` ENUM: `Открыт` -> `Обработан` -> `Назначен` -> `Подписан` | `Отмена`.
3. **Ручное связывание «Лид -> Продавец»:**
   - Ограничение `UNIQUE` на `leads.seller_phone` исключает связывавание продавца с более чем одним лидом.
   - Триггер `validate_lead_seller_link_trigger` при установке `seller_phone` автоматически выставляет статус `Подписан` и фиксирует `linked_at = now()`.
   - В UI выборки для консультанта доступны только те продавцы, чей `seller_phone` отсутствует в `leads.seller_phone`.
4. **Нормализация телефонных номеров:**
   - В таблицах `sellers`, `payments`, `connections` номер хранится строго в международном цифровом формате `996XXXXXXXXX` (12 цифр без символа `+`).
   - В таблице `leads` номер хранится как 9 цифр (`phone`) и код юрисдикции (`country_code = '996'`).
5. **Изоляция и персистентность менеджеров при API Upsert:**
   - При синхронизации с API `api.sotka.kg` операция `upsert` в `sellers` не должна перезаписывать локально установленное поле `manager_id`.

## 5. UI/UX Спецификация (Apple Island & DataJournal)

- **Эстетика Apple Island:**
  - Матовые парящие островки (`backdrop-blur-xl bg-white/75 border border-white/20 shadow-sm` для светлой темы; `backdrop-blur-xl bg-zinc-900/75 border border-zinc-800/40 shadow-2xl` для тёмной).
  - Скругления `rounded-2xl` и `rounded-3xl`.
  - Отсутствие эмодзи. Линейные иконки `lucide-react`.
- **Адаптивный лейаут:**
  - **Десктоп (от 1024px):** Скрываемый/сворачиваемый матовый сайдбар (`w-64` / `w-18`), матовый Top Header (`fixed top-4 right-4`), независимый скролл-контейнер.
  - **Мобильный (до 1023px):** Верхний островок с поиском (раскрывающийся инпут) и фильтром; нижний Bottom Bar Island с ключевыми разделами; плавающий FAB `w-14 h-14` в нижнем правом углу (`bottom-24 right-5`) под большой палец.
- **Полиморфный реестр `DataJournal`:**
  - **Table View (ПК по умолчанию):** Sticky-шапка, кастомизация колонок (видимость, порядок), изменение ширины drag-to-resize, in-cell статусные бейджи.
  - **Card View (Мобильный по умолчанию):** Кнопки в 1 клик (`tel:`, `wa.me`, Instagram direct), in-place переключение статуса через выпадающий список прямо в карточке.
  - Универсальный конструктор фильтров, сортировка, серверная пагинация (10, 25, 50, 100).
- **Скрипты продаж:**
  - Мобильный Bottom Sheet с кликом для копирования в буфер обмена и виброоткликом `navigator.vibrate(50)`.

## 6. Декомпозиция этапов реализации

В соответствии с разделом 9 `ТЗ.md`:

1. **Этап 1 (Текущий приоритет):**
   - Инициализация проекта Next.js (App Router, TypeScript, Tailwind CSS, Lucide React).
   - Развертывание DDL-схемы в PostgreSQL / Supabase:
     - 6 типов ENUM: `user_role`, `lead_status`, `client_lifecycle_status`, `maintenance_status`, `payout_category_type`, `seller_moderation_status`.
     - 11 таблиц: `users`, `leads`, `sellers`, `payments`, `connections`, `employee_rates`, `client_maintenance`, `employee_payouts`, `outlets`, `plans`, `plans_history`.
     - Индексы для ускорения выборок.
     - Хранимые функции и триггеры (`trg_lock_lead_delete`, `trg_audit_plan_price`, `trg_validate_lead_seller_link`).
     - Функции определения контекста (`get_current_user_role`, `get_current_crm_user_id`).
     - Политики Row Level Security (RLS) для изоляции доступа.
   - Настройка клиентов Supabase (Browser Client, Server Client, Admin Service Role Client).
   - Генерация TypeScript типов БД (`types/database.types.ts`).
   - Модуль аутентификации (страница входа `/login`, сессии, проверка роли, защищенные маршруты Middleware).
   - Базовый глобальный лейаут Apple Island (Desktop Sidebar + Top Header, Mobile Top/Bottom Bar + FAB, переключатель светлой/тёмной темы).
2. **Этап 2:** Модуль «Лиды» (CRUD, полиморфный `DataJournal`, Mobile-first карточки со свайпами, быстрые кнопки связи, модуль скриптов продаж с haptic feedback).
3. **Этап 3:** Серверный интеграционный модуль синхронизации с `api.sotka.kg` (`/api/sync/sotka`, Bearer auth, upsert с сохранением связей).
4. **Этап 4:** Модуль маппинга продавцов и управления связями (1:1 закрепление, расчет комиссии за подключение, контроль лимита сопровождения).
5. **Этап 5:** Финансовый блок, справочники, дашборды KPI по ролям, аудит и подготовка к production.
