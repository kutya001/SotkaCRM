# Архитектурный план: Оптимизация производительности, Телефонные коды СНГ, Унификация кнопки «Добавить» и Архитектура Sotka API

**Дата:** 20-09-2026  
**Категория:** Планирование и декомпозиция задач

---

## 1. Контекст и цели
Пользователь обозначил четыре ключевые проблемы в работе системы:
1. Замедленная загрузка приложения при первом входе, ощущение «определения модулей на ходу» (мигание навигации, позднее появление Справочников).
2. Форма Лидов: код страны должен стоять по умолчанию 996 рядом с номером телефона в одной строке, с выбором из списка основных стран СНГ.
3. Размещение кнопки «Добавить»: дублирование кнопок на мобильных (в тулбаре и в нижнем углу), неудачное расположение в Лидах на ПК. Задача: на смартфонах оставить строго одну кнопку под правый палец, на ПК разместить кнопку снизу справа в виде аккуратного квадратика.
4. Ошибка 500 при синхронизации Sotka API (`POST /api/sync/sotka 500`). Требуется внедрить предоставленную спецификацию BFF, Phone Sanitizer, `extractArrayData`, `flattenObject` и отказоустойчивый клиент `lib/sotka/client.ts`.

## 2. Декомпозиция шагов

### Шаг 1: Оптимизация производительности и AuthProvider
- Превратить браузерный клиент Supabase в синглтон (`lib/supabase/client.ts`).
- Создать `components/auth/AuthProvider.tsx` с синхронной инициализацией из `localStorage` (`sotka_user_profile`).
- Подключить `AuthProvider` в корень `app/layout.tsx`.
- В `components/layout/AppLayout.tsx` автоматически использовать роль и профиль из контекста.

### Шаг 2: Композитное поле телефона и коды стран СНГ
- Создать константу `CIS_COUNTRIES`:
  - Кыргызстан (+996)
  - Казахстан (+7)
  - Россия (+7)
  - Узбекистан (+998)
  - Таджикистан (+992)
  - Беларусь (+375)
  - Азербайджан (+994)
  - Армения (+374)
  - Туркменистан (+993)
  - Молдова (+373)
- В `components/ui/EntityModal.tsx` поддержать композитный рендер для полей типа `phone`:
  - Выпадающий список кодов СНГ (default: 996) слева + инпут номера телефона справа в одной строке.
  - В режиме `view`: отображение `+{country_code} {phone}`.
- В `app/leads/page.tsx` скрыть отдельное поле `country_code` из списка полей, так как оно встроено в поле телефона.

### Шаг 3: Унификация кнопки «Добавить»
- В `components/layout/AppLayout.tsx` добавить пропсы `onCreateClick` и `createTooltip`.
- Отрендерить плавающую кнопку создания:
  - Мобильные (<1024px): `fixed bottom-24 right-5 z-50 w-14 h-14 rounded-full` под правый большой палец.
  - Десктоп (>=1024px): `fixed bottom-8 right-8 z-40 w-12 h-12 rounded-2xl` — стильный квадратный островок.
- На страницах (`/leads`, `/payouts`, `/plans`) убрать дублирующую кнопку `[+]` из тулбара реестра и передавать `onCreateClick` в `AppLayout`. В тулбаре Лидов оставить только кнопку `[Скрипты продаж]`.

### Шаг 4: Реализация спецификации Sotka API (BFF)
- Создать `lib/sotka/types.ts` с описанием `FetchParams` и DTO.
- Создать `lib/sotka/normalizers.ts`:
  - `sanitizePhone(phone: string)`
  - `extractArrayData(json: unknown)`
  - `flattenObject(obj: Record<string, any>)`
- Создать `lib/sotka/client.ts` с поддержкой куки `sotka_access_token`, интерполяцией путей, unwrap данных.
- Обновить `app/api/sync/sotka/route.ts` для использования нового клиента, устранения причин 500 ошибки и сохранения локальных связок `manager_id`.

### Шаг 5: Верификация и тестирование
- `npx tsc --noEmit`
- `npm run build`
- Фиксация отчета в `.antigravity/results/` и коммит в ветку `main`.
