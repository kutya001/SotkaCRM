# План реализации: Синхронизация с API api.sotka.kg, исправление Web Manifest и переход на строгие логины

Данный этап расширяет функционал Этапа 5, исправляет критическую ошибку клиентского веб-манифеста PWA и полностью переводит систему аутентификации и регистрации сотрудников на строгие системные логины без использования email в пользовательском интерфейсе.

---

## 1. Архитектурный анализ и постановка задачи

### 1.1. Ошибка клиентского манифеста (`manifest.json:1 Manifest: Line: 1, column: 1, Syntax error`)
* **Причина:** Браузер запрашивает `/manifest.json` из-за метаданных в `app/layout.tsx`, однако файл `public/manifest.json` физически отсутствует, а Next.js Metadata Route `app/manifest.ts` не был создан. Сервер Next.js возвращает стандартный HTML-документ ошибки 404 (`<!DOCTYPE html>...`), что приводит к сбою JSON-парсера браузера.
* **Решение:** 
  1. Создать `app/manifest.ts` (стандартный генератор Web Manifest в Next.js App Router).
  2. Создать статический fallback-манифест `public/manifest.json` по требуемой спецификации.
  3. Создать векторную иконку `public/icon.svg` в фирменном стиле (Glassmorphism / Layers).
  4. Обновить конфигурацию в `app/layout.tsx`.

### 1.2. Перевод аутентификации и регистрации строго на логины (`login`)
* **Существующее состояние:** Ядро Supabase Auth требует email для метода `signInWithPassword`. Ранее логины дополнялись до `@sotka.kg`, а в UI отображалось поле «Логин или Email».
* **Целевое состояние:**
  1. В UI — исключительно поле с лейблом **«Логин»** (плейсхолдер: `admin, consultant1, smm_operator`). Полное отсутствие упоминаний почты.
  2. В базе данных: гарантировать `UNIQUE` и `NOT NULL` для `public.users.login`.
  3. Внутренняя инкапсуляция: синтетический домен `${login.toLowerCase()}@internal.sotka.kg`, генерируемый исключительно на сервере и невидимый пользователю.
  4. Создание функции базы данных `public.create_crm_user(...)` со статусом `SECURITY DEFINER` и проверкой роли `admin` для атомарной регистрации пользователя в `auth.users`, `auth.identities` и `public.users`.
  5. Миграция существующих тестовых аккаунтов на домен `@internal.sotka.kg`.
  6. Server Action `createCrmUser(...)` для администратора.

  - Вызывает функцию создания пользователя `create_crm_user` (или `createAdminClient`).
