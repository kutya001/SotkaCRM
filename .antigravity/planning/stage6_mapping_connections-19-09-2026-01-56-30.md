# План реализации Этапа 6: Ручной маппинг «Лид → Продавец» и модуль «Подключения» (/connections)

Данный этап реализует ключевой бизнес-сценарий SotkaCRM — конверсию входящей заявки (лида) в привязанного клиента платформы Sotka с одновременным закреплением куратора, расчетом комиссионного вознаграждения консультанта за первичное подключение (connection fee) и формированием записи в реестре «Подключения».

---

## 1. Архитектурный анализ и бизнес-правила

### 1.1. Механизм изоляции свободных продавцов
* Связывание лида с продавцом платформы выполняется строго 1:1 по внешнему ключу `leads.seller_phone = sellers.seller_phone`.
* В выборке доступных для связывания продавцов должны отображаться исключительно те, чей `seller_phone` отсутствует в столбце `leads.seller_phone` (учитывая `seller_phone IS NOT NULL`).
* Поиск осуществляется по ФИО продавца, названию торговой точки (`store`) и номеру телефона.
* Сортировка: по дате регистрации (`registered_at DESC`) или времени последней активности.

### 1.2. Расчет комиссионного вознаграждения консультанта
* Стоимость тарифа продавца берется из таблицы `plans.price` на момент закрытия сделки (напр., PLN-BASE: 2 500 KGS, PLN-PREM: 5 000 KGS, PLN-CORP: 12 000 KGS).
* Процент вознаграждения за подключение (`connection_fee_percent`) извлекается из таблицы `employee_rates` для ответственного консультанта (`effective_from <= current_month`, по умолчанию 30.00%).
* Сумма вознаграждения рассчитывается по формуле:
  $$\text{connection\_fee\_amount} = \frac{\text{plan\_price} \times \text{connection\_fee\_percent}}{100}$$
* Расчетный месяц начисления (`accrual_month`): текущий месяц в формате `YYYY-MM` (например, `2026-09`).

### 1.3. Атомарная транзакция связывания (`linkLeadToSeller`)
Выполняется атомарно через Server Action или хранимую функцию базы данных:
1. Валидация: проверка, что лид не подписан/не отменен, а продавец еще не занят другим лидом.
2. `leads`: обновление `seller_phone = selected_phone`, `status = 'Подписан'`, `linked_at = now()`.
3. `sellers`: закрепление куратора `manager_id = consultant_id`.
4. `connections`: создание записи закрепления со статусом `status = 'подключен'`, `client_status = 'новый'`, расчетным месяцем и суммой бонуса.

### 1.4. Реестр «Подключения» (`app/connections/page.tsx`)
* Построен на базе универсального компонента `DataJournal`:
  - Десктоп: табличный вид со sticky-шапкой, сортировкой и быстрой фильтрацией.
  - Мобильные: карточный вид со статусами и кнопками связи.
* Верхний блок KPI: «Всего подключений», «Новые за месяц», «Сумма бонусов к выплате (KGS)», «В сопровождении».
* Фильтрация: селектор расчетного месяца (`accrual_month`) и статуса сопровождения (`client_lifecycle_status`).
* Модальное окно `EntityModal`: просмотр реквизитов подключения и редактирование статуса сопровождения для администратора.
* Ролевой доступ (RBAC):
  - `admin`: видит все подключения, может менять статус сопровождения.
  - `consultant`: видит строго свои закрепления (`manager_id = current_user_id`).
  - `smm`: доступ заблокирован (редирект на `/leads`).

2. `npm run build` — подтверждение успешной сборки production Next.js 15 (маршрут `○ /connections`).

### Ручная проверка
1. Проверка выборки свободных продавцов (`leads.seller_phone IS NULL`).
2. Проведение связывания лида с продавцом:
   - Проверка перевода лида в статус `Подписан` и заполнения `linked_at`.
   - Проверка создания записи в `connections` с корректным расчетом суммы комиссии (30%).
   - Проверка назначения куратора в `sellers.manager_id`.
3. Проверка видимости в `/connections`:
   - Под администратором (`admin`) — видны все подключения.
   - Под консультантом (`consultant1`) — видны только свои закрепления.
   - Под `smm_operator` — срабатывает редирект на `/leads`.
