# План интеграции интерактивной Swagger UI документации API (/docs)

**Дата:** 27-09-2026 11:28:00  
**Целевой релиз:** SotkaCRM 1.0  
**Ветка:** `main`

---

## 1. Цель и задачи
Интеграция интерактивной веб-документации OpenAPI 3.0.3 через `swagger-ui-react` по маршруту `/docs`, охватывающей внутренний шлюз синхронизации (`/api/sync/sotka`) и внешние контракты взаимодействия с платформой Sotka HQ (`/api/private/v1/admin/sellers-overview/`).

---

## 2. Пошаговый план реализации

### Этап 1: Установка зависимостей
- Установить `swagger-ui-react` и `@types/swagger-ui-react` (dev-зависимость).

### Этап 2: Создание спецификации OpenAPI 3.0.3 (`public/openapi.json`)
- Разместить полный файл `public/openapi.json` со спецификацией всех эндпоинтов:
  * `GET /api/sync/sotka` — статус шлюза синхронизации.
  * `POST /api/sync/sotka` — вебхук синхронизации данных из Sotka.
  * `GET /api/private/v1/admin/sellers-overview/` — обзор продавцов Sotka HQ.
  * `GET /api/private/v1/admin/sellers-overview/{organization_id}/` — детальная карточка продавца.
  * Схемы компонентов: `ErrorResponse`, `SyncWebhookPayload`, `SellerOverviewItem`, `SellersOverviewResponse`, `SellerDetailResponse`.

### Этап 3: Стилизация под темную тему CRM (`app/docs/swagger-theme.css`)
- Создать изолированный CSS-файл `app/docs/swagger-theme.css`.
- Оформить фон (`#09090b` / `#18181b`), типографику, плавающие стеклянные блоки в стиле Apple Island, контрастные бейджи HTTP-методов (GET, POST), таблицы параметров и ответов.
- Изолировать селекторы через контейнер `.swagger-dark-theme`, чтобы не затронуть глобальные Tailwind-стили CRM.

### Этап 4: Разработка клиентского компонента (`components/docs/SwaggerDocs.tsx`)
- Реализовать `'use client'` компонент `SwaggerDocs`.
- Динамически загружать `swagger-ui-react` через `next/dynamic` с `{ ssr: false }` для предотвращения гидратационных ошибок в App Router.
- Отображать Apple Island загрузочный спиннер при начальной загрузке.
- Подключить `swagger-ui-react/swagger-ui.css` и `swagger-theme.css`.

### Этап 5: Страница документации (`app/docs/page.tsx`) и настройка Middleware
- Создать серверный компонент страницы `app/docs/page.tsx` с метаданными `metadata = { title: 'API Gateway Docs | SotkaCRM' }`.
- В `lib/supabase/middleware.ts` добавить `/docs` и `/openapi.json` в список публичных страниц (без редиректа на `/login`).

### Этап 6: Тестирование и верификация
- Проверить сборку TypeScript: `npx tsc --noEmit`.
- Проверить production сборку: `npm run build`.
- Создать артефакт результатов `.antigravity/results/swagger_api_docs_verified-27-09-2026-11-xx-xx.md`.
- Зафиксировать изменения в git.
