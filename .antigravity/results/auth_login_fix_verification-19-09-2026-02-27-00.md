# Протокол устранения ошибки аутентификации SotkaCRM

- **Дата:** 19-09-2026 02:27:00
- **Сущность:** Модуль авторизации и аутентификации (`/login`, `app/auth/actions.ts`)
- **Статус:** Исправлено и верифицировано

---

## 1. Причина сбоя

1. **Ошибка сканирования схемы в GoTrue (Supabase Auth):**
   В таблице `auth.users` строковые поля токенов (`confirmation_token`, `recovery_token`, `email_change_token_new`, `email_change` и др.) содержали значения `NULL`. Внутренний драйвер GoTrue при вызове `sql.Scan` на тип string падал с системной ошибкой `500 Database error querying schema`.
2. **Блокировка RLS для неаутентифицированного клиента:**
   В серверном экшене `loginAction` до вызова `signInWithPassword` выполнялся предварительный запрос к таблице `public.users` через анонимный инстанс Supabase. Политика безопасности RLS разрешала чтение только роли `authenticated`, из-за чего анонимный запрос возвращал 0 строк (`PGRST116`) с отображением ошибки «Пользователь с таким логином не найден в системе».

---

## 2. Реализованные исправления

1. **Нормализация таблицы `auth.users` в СУБД:**
   - Все поля токенов переведены из `NULL` в пустые строки `''`.
   - Проверены и синхронизированы хэши паролей для учетных записей:
     * `admin` (`admin@internal.sotka.kg`) — пароль `admin123456`
     * `consultant1` (`consultant1@internal.sotka.kg`) — пароль `admin123456`
     * `smm_operator` (`smm_operator@internal.sotka.kg`) — пароль `admin123456`
2. **Обновление политик RLS (`DB.md`, `001_initial_schema.sql`):**
   - Добавлена политика `users_anon_select_policy` (`FOR SELECT TO anon USING (true)`), разрешающая анонимное чтение публичных данных профилей для верификации статуса.
3. **Оптимизация серверного экшена `app/auth/actions.ts`:**
   - Нормализация логина (удаление префикса `@` и домена `@internal.sotka.kg`).
   - Прямой вызов `signInWithPassword` с синтетическим email.
   - Загрузка профиля `public.users` по `auth_id` уже после успешной валидации сессии с проверкой флага `is_active`.
4. **Синхронизация первичных данных (`supabase/seed.sql`):**
   - Включена вставка `auth.users` и `auth.identities` с непустыми токенами и хэшами bcrypt.
