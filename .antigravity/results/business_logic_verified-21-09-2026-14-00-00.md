## 1. Выполненные задачи и архитектурные изменения

### 1.1. Ролевая модель и воронка лидов (`/leads`)
1. **Администратор (Координация):**
   - Полный доступ ко всем этапам воронки.
   - Смена статуса на «Назначен» с одновременным назначением ответственного консультанта (`assigned_to`).
2. **SMM-специалист:**
   - Заводит входящие лиды со статусом «Открыт» без назначения консультанта (`assigned_to = null`).
   - Имеет право модификации карточки и смены статуса только между «Открыт» и «Обработан».
   - После перевода лида администратором в статус «Назначен», «Подписан» или «Отмена» для SMM карточка лида автоматически переходит в режим только для чтения (`view`). Любые попытки изменения блокируются как на клиенте, так и на сервере через Server Actions и RLS (`leads_update_policy`).
3. **Консультант:**
   - Видит исключительно закрепленные за ним лиды (`assigned_to = current_user_id`) в статусах «Назначен», «Подписан», «Отмена».
   - Статусы «Открыт» и «Обработан» скрыты.
   - Права редактирования строго ограничены полями `status` и `comment`. Поля `client_name`, `phone`, `country_code`, `instagram`, `assigned_to` заблокированы для изменения.
   - В интерфейсе для консультанта адаптированы KPI-виджеты (4 метрики вместо 5, без отвлекающих глобальных воронок).

### 1.2. Модуль «Продавцы» (`/sellers`) и быстрое связывание с лидами
1. **Быстрое назначение консультанта:**
   - Администратор может в один клик назначить/сменить куратора продавца непосредственно из реестра или карточки.
2. **Колонка «Лид» (`linked_lead`):**
   - В реестр продавцов выведен статус связи с лидом: плашка с именем лида и телефоном при наличии привязки, либо бейдж «Не привязан» с кнопкой быстрого связывания «Привязать лид» для администратора.
3. **Модальное окно связывания `LinkSellerLeadModal`:**
   - Администратор выбирает активный свободный лид (`seller_phone IS NULL` и `status != 'Отмена'`).
   - Выполняется атомарная транзакция через RPC `link_lead_to_seller`:
     - Назначение ответственного консультанта продавцу из лида (`sellers.manager_id = leads.assigned_to`).
     - Привязка номера продавца к лиду (`leads.seller_phone = seller_phone`).
     - Автоматический перевод лида в статус «Подписан» с фиксацией времени `linked_at = now()`.
     - Создание/обновление записи в `connections` с мгновенным расчетом комиссии по тарифу и персональной процентной ставке консультанта.

### 1.3. Справочники («Тарифы» `/plans` и «Ставки» `/rates`)
1. **Удаление тарифов:**
   - Администратор может удалять неиспользуемые тарифные планы.
   - Встроена строгая валидация целостности связей: при наличии активных продавцов или транзакций подключений удаление блокируется с выводом количества блокирующих записей.
2. **Удаление/Сброс ставок сотрудников:**
   - Администратор может удалять индивидуальные ставки сотрудников, сбрасывая их на дефолтные платформенные значения (30% подключение / 10% абонплата).

### 1.4. Мобильная навигация (`MobileBottomBar`)
- Добавлен пункт «Главная» (`/`) с контурной иконкой Lucide `LayoutDashboard` в качестве первого элемента навигационного бара.
