## 1. Выявленные и устраненные проблемы

### 1.1. Ошибки 404 (`/payments` и `/analytics` при переходе и RSC-prefetch)
- **Причина:** В навигации (`DesktopSidebar.tsx`, `MobileBottomBar.tsx`) ссылка «Финансы» для роли консультанта вела на `/payments` вместо существующего маршрута `/payouts`, а пункт «Аналитика» ссылался на отсутствующую страницу `/analytics`. При рендере Next.js инициировал автоматическую предзагрузку (`?_rsc=...`), вызывавшую ошибки 404 в консоли браузера.
- **Решение:**
  1. В `DesktopSidebar.tsx` удален несуществующий пункт `/payments`, сохранен `/payouts` («Выплаты»).
  2. В `MobileBottomBar.tsx` ссылка для всех авторизованных сотрудников унифицирована на `/payouts`.
  3. В `next.config.ts` настроен перманентный серверный редирект с `/payments` на `/payouts` (`308 Permanent Redirect`).
  4. Создана страница `app/analytics/page.tsx` со сводными метриками воронки, конверсией, балансами продавцов и фондом выплат в стиле Apple Island Glassmorphism.

### 1.2. Ошибка 500 `POST /leads?action=create`
- **Причина:**
  1. В `EntityModal` при создании лида поле `assigned_to` по умолчанию передавалось как пустая строка `""` (из опции «— Не назначен —»). Схема `z.string().uuid()` падала на валидации, а Server Action выбрасывал необработанный `throw new Error()`, который Next.js маскировал в HTTP 500.
  2. Кнопка мобильного добавления FAB перенаправляла на `/leads?action=create`, но страница не считывала этот параметр для открытия модального окна создания.
- **Решение:**
  1. В `lib/validations/index.ts` схема `LeadCreateSchema` дополнена препроцессором `z.preprocess`, преобразующим пустую строку `""` в `null` для UUID-поля `assigned_to`.
  2. В `app/leads/actions.ts` все мутации (`createLead`, `updateLead`, `updateLeadStatus`, `cancelLead`) изолированы в блоках `try...catch` и возвращают типизированный ответ `{ success: boolean, error?: string, lead?: LeadItem }`, исключая неконтролируемые исключения сервера.
  3. В `app/leads/page.tsx` добавлена обработка `useSearchParams()` (внутри `<React.Suspense>`) для автоматического открытия окна создания при наличии параметра `action=create`.

### 1.3. Ошибка 500 `POST /api/sync/sotka`
- **Причина:** Инициализация сервисного клиента `createAdminClient()` и проверка сессии находились вне блока `try...catch`. При отсутствии серверных переменных (`SUPABASE_SERVICE_ROLE_KEY`, `SOTKA_API_PHONE`, `SOTKA_API_PASSWORD`) в деплое Vercel происходил сбой среды исполнения Node.js с генерацией статуса 500.
- **Решение:**
  1. Обработчик `handleSync` полностью обернут в `try...catch`.
  2. На входе выполняется валидация наличия критических переменных с возвратом информативного JSON-ответа при их отсутствии.
