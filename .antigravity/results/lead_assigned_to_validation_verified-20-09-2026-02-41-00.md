## 1. Выполненные доработки

### 1.1. Нормализация входных данных в Server Action (`app/leads/actions.ts`)
- Реализована функция нормализации внешних ключей `normalizeNullableUuid(val: unknown): string | null`.
- Все строковые значения `""`, пробелы, `"none"`, `"null"`, `"undefined"` и дефисы (`"— Не назначен —"`) гарантированно преобразуются в `null` до передачи в валидатор Zod и до выполнения SQL-запроса `insert` / `update` в Supabase.
- Исключена передача пустых строк `""` в поле типа `UUID` базы данных PostgreSQL.

### 1.2. Корректировка схемы валидации Zod (`lib/validations/index.ts`)
- Поле `assigned_to` в `LeadCreateSchema` дополнено препроцессором `z.preprocess((val) => normalizeNullableUuid(val), z.string().uuid('Некорректный идентификатор ответственного').nullable().optional()).default(null)`.
- Схема успешно пропускает:
  - Пустую строку `""` -> нормализуется в `null`;
  - Пробелы `"   "` -> нормализуются в `null`;
  - Плейсхолдер `"— Не назначен —"` -> нормализуется в `null`;
  - `null` и `undefined` -> валидны, возвращается `null`;
  - Валидный UUID (`123e4567-e89b-12d3-a456-426614174000`) -> сохраняется без изменений;
  - Некорректную строку (`"invalid-uuid"`) -> отклоняет с сообщением `"Некорректный идентификатор ответственного"`.

### 1.3. Схема базы данных
- Таблица `leads` в PostgreSQL имеет определение: `assigned_to UUID NULL REFERENCES users(user_id) ON DELETE SET NULL`. Значение `NULL` полностью поддерживается СУБД.

### 1.4. Ликвидация дублирования тостов в `EntityModal` и `app/leads/page.tsx`
- В `components/ui/EntityModal.tsx` блок `catch` теперь извлекает точное серверное сообщение: `showToast(err?.message || 'Произошла ошибка при сохранении', 'error')`.
- В `app/leads/page.tsx` удалены избыточные промежуточные вызовы `showToast` перед `throw new Error(...)` в `handleCreateLead`, `handleSaveLead` и `handleStatusChangeInModal`.
- При любой ошибке валидации или сервера на экране пользователя отображается **ровно один тост** с точным текстом ошибки от сервера.
