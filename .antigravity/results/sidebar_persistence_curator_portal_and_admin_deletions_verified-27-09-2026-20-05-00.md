## 1. Выполненные задачи и архитектурные изменения

### 1.1. Защита от сбоя парсинга ответов сервера (`lib/api/client.ts`)
* В `executeFetch` внедрена проверка статуса `204 No Content` (`data = null`).
* При `Content-Type: application/json` парсинг обернут в безопасный `.json().catch(() => null)`.
* При получении не-JSON ошибок (HTML страницы от Cloudflare/Vercel/шлюза или текст) выполняется автоматическая очистка HTML-разметки и возврат информативного текста ошибки вместо системного сбоя Next.js `An unexpected response was received from the server`.
* В `api.payouts` добавлен метод `delete: (id: string) => Promise<{ success: boolean; deleted_id: string }>` с каскадной инвалидацией неймспейсов `payouts`, `connections`, `profile`, `dashboard`, `analytics`.

### 1.2. Фиксация свернутого состояния сайдбара (`components/layout/AppLayout.tsx`)
* Состояние сворачивания `isCollapsed` синхронизировано с `localStorage` (ключ `sotka_sidebar_collapsed`).
* Проверка в `useEffect` предотвращает расхождения при SSR-гидратации.
* При переходе между страницами (`/leads`, `/sellers`, `/connections`, `/payouts`, `/employees`, `/plans`, `/profile`) состояние сайдбара сохраняется и не сбрасывается.

### 1.3. React Portal для выпадающего списка кураторов (`components/sellers/CuratorSelectDropdown.tsx`)
* Всплывающее меню кураторов вынесено из ячейки `<td>` в корень `document.body` через `createPortal`.
* Задано абсолютное изолированное позиционирование `fixed z-[99999]`.
* Координаты (`top`, `left`, `width`) динамически вычисляются по `getBoundingClientRect()` триггера.
* Реализовано определение переполнения снизу экрана: при нехватке места меню разворачивается вверх над кнопкой триггера (`translateY(-100%)`).
* Слушатели событий `mousedown`, `keydown (Escape)`, `scroll` и `resize` корректно закрывают всплывающее меню при внешних взаимодействиях.
* Цветовые схемы кураторов изолированы, янтарный фон триггера не каскадируется на список.

### 1.4. Удаление подключения с каскадным сбросом куратора (Admin Only)
* **API (`app/api/v1/connections/[id]/route.ts`):**
  - Строгая авторизация: разрешено исключительно роли `admin` (`requireAdmin()`, для остальных 403 Forbidden).
  - При удалении сначала извлекается `seller_phone`.
  - В таблице `sellers` сбрасывается куратор: `manager_id = NULL`.
  - Удаляются связанные начисления из `connection_accruals` и `client_maintenance`.
  - Удаляется сама запись из `connections`.
* **Интерфейс (`app/connections/page.tsx`):**
  - Пункт «Удалить подключение» доступен в контекстном меню строки (ПКМ) и в модальном окне деталей (только для `admin`).
  - Диалоговое окно подтверждения с предупреждением о сбросе куратора и удалении начислений.
  - Инвалидация кэша `connections` и автоматическое обновление реестра через `fetchData()`.

### 1.5. Удаление выплаты с разблокировкой начислений (Admin Only)
* **API (`app/api/v1/payouts/[id]/route.ts`):**
  - Строгая авторизация `requireAdmin()`.
  - До физического удаления выплаты из `employee_payouts` все связанные начисления в `connection_accruals` переводятся в статус ожидания: `is_paid = false, payout_id = NULL, paid_at = NULL`.
  - Удаляется запись о выплате.
* **Интерфейс (`app/payouts/page.tsx`):**
  - Пункт «Удалить выплату» доступен в контекстном меню (ПКМ) и в модальном окне деталей проводки (только для `admin`).
  - Модальное окно подтверждения удаления с предупреждением о возврате начислений в расчетный лист.
  - Инвалидация кэшей `payouts` и `connections`, обновление реестра через `fetchData()`.

### 1.6. Синхронизация документации (`DB.md`, `public/openapi.json`)
* В `DB.md` зафиксированы каскадные правила удаления для таблиц `connections` и `employee_payouts`.
* В `public/openapi.json` обновлены спецификации эндпоинтов `DELETE /api/v1/connections/{id}` и `DELETE /api/v1/payouts/{id}` с описанием логики сброса куратора и разблокировки начислений.
