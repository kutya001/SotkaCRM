## 1. Выполненные задачи и архитектурные решения

### 1.1. Исправление 400 Bad Request на маршруте `POST /api/v1/connections/accrue-all`
* **Проблема:** Несоответствие схем и названий полей (`settlement_month` vs `month`) между клиентом и сервером приводило к сбою валидации Zod и отказу в начислении бонусов.
* **Решение:**
  * Обработчик `app/api/v1/connections/accrue-all/route.ts` адаптирован для полиморфного парсинга тела запроса (`settlement_month`, `month` или `settlementMonth`).
  * При отсутствии параметров или пустом теле запроса автоматически устанавливается текущий месяц в формате `YYYY-MM`.
  * Вызов хранимой функции переведен на атомарную процедуру `process_unified_connection_accruals(p_settlement_month)` с резервным вызовом `accrue_all_connections_bonuses`.
  * В клиентском SDK `lib/api/client.ts` метод `api.connections.accrueAll(month)` отправляет оба ключа `{ month, settlement_month: month }`.

### 1.2. Детерминированная сортировка реестра продавцов (Sellers)
* **Проблема:** При назначении куратора строка продавца перемещалась в списке из-за сортировки по `updated_at`.
* **Решение:**
  * В API-маршруте `app/api/v1/sellers/route.ts` и серверном экшене `app/sellers/actions.ts` зафиксирована стабильная сортировка по дате регистрации и создания:
    ```typescript
    query = query
      .order('registered_at', { ascending, nullsFirst: false })
      .order('created_at', { ascending: false });
    ```
  * Назначение куратора больше не сдвигает позицию продавца в реестре.

### 1.3. Физическое удаление лидов администратором (Hard-Delete Leads)
* **База данных:**
  * Создана миграция `supabase/migrations/020_hard_delete_leads_and_unified_accruals.sql`.
  * Удален безусловный триггер `prevent_lead_delete`, блокировавший любое удаление лидов.
  * Создан триггер `trg_check_lead_delete` и функция `check_lead_deletion_permission()`, разрешающие физическое удаление (`DELETE FROM leads`) строго для роли `admin` (`public.get_current_user_role() = 'admin'`).
  * Добавлена RLS-политика `leads_delete_policy` для роли `admin`.
* **API:**
  * В маршруте `DELETE /api/v1/leads/[id]` реализовано физическое удаление `supabase.from('leads').delete().eq('lead_id', id)` при проверке роли администратора (`profile.role === 'admin'`).
* **Пользовательский интерфейс (`app/leads/page.tsx`, `components/ui/EntityModal.tsx`):**
  * В контекстное меню строк и карточек лидов добавлена кнопка «Удалить навсегда» с иконкой `Trash2` (отображается строго для роли `admin`).
  * В модальное окно деталей лида `EntityModal` добавлена кнопка «Удалить навсегда» в нижнем баре (слева).
  * Реализован диалог подтверждения удаления: «Вы действительно хотите безвозвратно удалить этот лид из базы? Запись будет физически удалена без возможности восстановления».
  * При подтверждении вызывается `api.leads.delete(lead_id)`, выводится уведомление, и лид мгновенно исключается из локального состояния `leads` без перезагрузки страницы.
