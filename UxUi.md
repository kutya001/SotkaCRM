# Спецификация UI/UX дизайна и интерфейсных компонентов SotkaCRM

Документ регламентирует требования к пользовательскому интерфейсу, дизайн-системе в стиле Apple Island (островной дизайн с матовыми поверхностями), адаптивным лейаутам, универсальному компоненту отображения данных (`DataJournal`), а также единой универсальной форме просмотра, редактирования и создания записей (`EntityModal`).

---

## 1. Концепция дизайн-системы (Apple Island Style & Glassmorphism)

Интерфейс строится по модульной «островной» концепции: функциональные блоки не прилипают к краям экрана монолитом, а представляют собой парящие скруглённые панели с эффектом матового стекла (Frosted Glass / Glassmorphism).

* **Поверхности и матовость:**
* Фон подложки: глубокий нейтральный фон (`bg-zinc-100` в светлой теме, `bg-black` или `bg-zinc-950` в тёмной).


* Плавающие островки: полупрозрачные контейнеры с размытием заднего плана (`backdrop-blur-xl bg-white/75 border border-white/20 shadow-sm` для светлой темы; `backdrop-blur-xl bg-zinc-900/75 border border-zinc-800/40 shadow-2xl` для тёмной темы).




* **Скругления (Border Radius):**
* Основные рабочие островки, модальные окна и карточки: `rounded-2xl` (16px) или `rounded-3xl` (24px).


* Кнопки, бейджи и поля ввода: `rounded-xl` (12px) или `rounded-full`.




* **Иконографика (Строгий контурный стиль):**
* Использование исключительно линейных контурных иконок пакета **Lucide React** (`stroke-width="1.75"` или `2`).


* **Полный запрет на эмодзи.** Все статусы, категории и кнопки снабжаются исключительно контурной векторной графикой.




* **Двойная цветовая палитра (Light / Dark Theme):**
* Переключение через CSS-переменные или Tailwind-класс `dark:`.


* Светлая тема: контрастный темный текст (`text-zinc-900`), мягкие серые границы (`border-zinc-200/60`), приглушенные акценты.


* Тёмная тема: нейтральный светлый текст (`text-zinc-100`), темные разделители (`border-zinc-800/60`), отсутствие чистого белого фона у панелей.

## 2. Глобальный архитектурный стандарт страниц (3-ярусная архитектура)

Все страницы системы с реестрами данных (`/leads`, `/sellers`, `/connections`, `/payouts`, `/plans`, `/rates`) строго подчиняются **единой трехъярусной архитектуре**. Промежуточные баннеры-островки (дублирующие H1 заголовки с бейджами и описанием), а также отдельные строки инлайн-селекторов фильтрации полностью ликвидированы.

```
       ДЕСКТОП (Desktop Mode)                            МОБИЛЬНЫЙ (Mobile Mode)
+------------------------------------------+       +-----------------------------------+
| ЯРУС 1: Top Header                       |       | ЯРУС 1: Mobile Header             |
| [Заголовок] [Поиск flex-1] [Фильтры (N)] |       | [Заголовок] [Лупа] [Фильтры (N)]  |
| [Синхронизация API] [Тема] [Аватар]      |       +-----------------------------------+
+------------------------------------------+       | ЯРУС 2: KPI Метрики               |
| Скрываемый  | ЯРУС 2: KPI Метрики        |       | [<- Горизонтальный snap-скролл ->]|
| боковой     | (Компактный ряд в 1 линию) |       +-----------------------------------+
| сайдбар     |----------------------------|       | ЯРУС 3: Тулбар DataJournal        |
| (Desktop)   | ЯРУС 3: Тулбар DataJournal |       | [Действия]        [Вид: Табл/Карт]|
|             | [Действия] [Колонки] [Вид] |       |-----------------------------------|
|             |----------------------------|       | Скроллируемый реестр карточек     |
|             | Скроллируемая таблица      |       | (Card View по умолчанию)          |
|             | (Table View по умолчанию)  |       |                                   |
|             |                            |       |               [ FAB: Кнопка «+» ] |
|             |                            |       +-----------------------------------+
|             |                            |       | Матовый нижний Bottom Bar         |
+------------------------------------------+       +-----------------------------------+
```

### 2.1. Ярус 1: Унифицированная шапка (TopHeader / MobileHeader)
* **Десктоп (TopHeader):**
  * Заголовок текущего модуля системы.
  * Поле быстрого поиска `searchQuery` (`flex-1 max-w-md`), сквозное для данных активного реестра, с кнопкой быстрой очистки `[✕]`.
  * Кнопка **«Фильтры»** с бейджем активных фильтров `filterCount` и всплывающим окном `filterContent` (`z-50`, автоматическое закрытие по клику вне области и по клавише `Escape`).
  * Кнопка синхронизации с Sotka API (только для роли `admin`).
  * Переключатель темы оформления (`Sun` / `Moon`).
  * Индикатор профиля и переход в настройки.
* **Мобильные устройства (MobileHeader):**
  * Заголовок страницы с автоматическим сокращением текста.
  * Кнопка **Лупа** (`Search`): при тапе трансформируется в полноэкранное поле ввода с автофокусом и кнопкой закрытия.
  * Кнопка **Фильтры** (`SlidersHorizontal`): открывает модальную матовую шторку снизу (Bottom Sheet) с селекторами и кнопкой сброса.
  * Минимальная зона нажатия (Touch Target) всех интерактивных элементов — **не менее 44×44 px**.

### 2.2. Ярус 2: Компактный блок метрик и KPI
* **Десктоп (от 1024px):** Компактные карточки в одну линию (сетка `grid-cols-4`, `grid-cols-5` или `grid-cols-6`), высота оптимизирована без пустого пространства.
* **Мобильные устройства (до 1023px):**
  * Для воронки Лидов (6 статусов) — компактная адаптивная двухрядная сетка `grid grid-cols-3 lg:grid-cols-6 gap-2 sm:gap-3` (3 колонки × 2 ряда). Все 6 метрик полностью умещаются на экране мобильного устройства без необходимости горизонтального свайпа и без вертикального растягивания.
  * Интерактивность: в модуле Лидов карточки являются активными кнопками быстрой фильтрации. Тап по статусу мгновенно фильтрует реестр с визуальной подсветкой выбранной карточки (`ring-2 ring-color`). Нажатие на «Всего в базе» или повторный тап по активному статусу сбрасывает фильтр.
  * Для реестра Продавцов (5 метрик) — адаптивная сетка `grid grid-cols-2 sm:grid-cols-3 lg:grid-cols-5 gap-2 sm:gap-3`, где карточка «Общий баланс» на мобильных экранах занимает весь нижний ряд (`col-span-2 sm:col-span-1`).
  * Для Подключений и Выплат (4 метрики) — компактная сетка `grid grid-cols-2 lg:grid-cols-4 gap-2 sm:gap-3`.

### 2.3. Ярус 3: Тулбар и универсальный реестр DataJournal
* **Левая часть тулбара:** Контекстные действия страницы (`customActions`):
  * Компактная кнопка добавления `[+]` с подсказкой (Tooltip: «Добавить лид», «Добавить тариф», «Оформить выплату») и размером `44×44 px`.
  * Быстрые вызовы регламентов: `[Скрипты продаж]` в Лидах, `[Биллинг сопровождения]` в Подключениях, `[Обновить]` в Продавцах и Тарифах.
* **Правая часть тулбара:**
  * Кнопка `[Колонки]` для настройки видимости столбцов (ПК-режим).
  * Переключатель `[Таблица / Карточки]` (Table / Cards View).
* **Исключение демонстрационных разделов:** Раздел `/demo` полностью удален из структуры проекта и боковой навигации. Реестры в рабочих модулях являются эталонным воплощением DataJournal.

## 3. Универсальный компонент отображения данных (`DataJournal`)

Единый универсальный полиморфный компонент `DataJournal` используется во всех реестрах системы (Лиды, Продавцы, Платежи, Выплаты, Торговые точки).

Компонент поддерживает два режима отображения с сохранением настроек пользователя в `localStorage`:

1. **Табличный вид (`Table View`):** открывается **по умолчанию на ПК**.


2. **Карточный вид (`Card View`):** открывается **по умолчанию на мобильных устройствах**.



### 3.1. Сравнительная матрица возможностей режимов

| Параметр | Табличный вид (Desktop Default) | Карточный вид (Mobile Default) |
| --- | --- | --- |
| **Отображение данных** | Многоколоночная компактная сетка

 | Лента плавающих матовых карточек

 |
| **Ширина столбцов** | Интерактивное изменение (drag-to-resize)

 | Адаптивная ширина карточки (100%)

 |
| **Порядок полей** | Drag-and-drop перемещение колонок

 | Фиксированная иерархия блоков карточки

 |
| **Видимость полей** | Чекбоксы в меню «Колонки»

 | Чекбоксы в меню «Настройка полей карточки»

 |
| **Сортировка** | Клик по шапке столбца (ASC/DESC/сброс)

 | Выпадающий список сортировки в тулбаре

 |
| **Фильтрация** | Универсальный inline-конструктор условий

 | Выдвижное модальное окно (Bottom Sheet)

 |
| **Быстрые действия** | Панель действий в строке / hover-панель

 | Нижний Action Bar прямо на карточке

 |

### 3.2. Быстрые действия в списках (`Quick Actions in Journal`)

Без необходимости открывать полную форму записи интерфейс журнала предоставляет доступ к экспресс-действиям:

* **Табличный вид (ПК):**
* In-cell переключение: клик по бейджу статуса открывает всплывающее меню прямой смены статуса (без открытия модалки).
* Закрепленная колонка быстрых действий справа: кнопки вызова карточки просмотра (`Eye`), быстрого перехода в мессенджер WhatsApp (`MessageCircle`), копирования телефона (`Copy`).


* **Карточный вид (Мобильные):**
* Action Bar внизу каждой карточки:
* Кнопка прямого GSM-вызова (`href="tel:..."`).


* Кнопка WhatsApp (`href="[https://wa.me/](https://wa.me/)..."`).


* Кнопка перехода в Instagram Direct.


* Компактный выпадающий селектор статуса.




* Клик по телу карточки открывает полную карточку записи в режиме просмотра (`view`).

## 4. Единая гибридная форма сущности (`EntityModal / EntityDrawer`)

Каждая запись в системе (Лид, Продавец, Выплата, Тариф, Связка) открывается в **единой универсальной форме**. Форма не разделяется на разные страницы, а динамически переключает режимы: **Просмотр (`view`)**, **Редактирование (`edit`)** и **Создание (`create`)**.

### 4.1. Адаптивный контейнер формы

* **На ПК (от 1024px):** Центрированный парящий матовый островок (`max-w-2xl w-full backdrop-blur-2xl bg-white/90 dark:bg-zinc-900/90 border border-white/20 dark:border-zinc-800/50 rounded-3xl shadow-2xl p-6`).
* **На смартфонах (до 1023px):** Выдвигающаяся снизу матовая шторка (Bottom Sheet / Drawer) со скруглением верхних углов `rounded-t-3xl` и индикатором свайпа закрытия вверху.

### 4.2. Режимы работы единой формы

```
+--------------------------------------------------------------------------+
|  ШАПКА: Название сущности / ID                 [Кнопка Edit] [Кнопка X]  |
+--------------------------------------------------------------------------+
|  [ОСТРОВОК БЫСТРЫХ ДЕЙСТВИЙ (Quick Actions)] (в режиме View)             |
|  [Статус: В работе] [Звонок] [WhatsApp] [Привязать продавца]             |
+--------------------------------------------------------------------------+
|  ТЕЛО ФОРМЫ (Скроллируемый блок полей):                                 |
|                                                                          |
|  * Неизменяемое поле:                                                   |
|    +------------------------------------------------------------------+  |
|    | ID: 7f8a9b2c-1234-5678-abcd-001122334455         [Иконка Copy]   |  |
|    +------------------------------------------------------------------+  |
|    (Визуально заблокировано, клик копирует значение с виброоткликом)     |
|                                                                          |
|  * Редактируемое поле:                                                   |
|    В режиме View: статичный текст / бейдж                                |
|    В режиме Edit / Create: активное поле ввода (Input / Select)          |
+--------------------------------------------------------------------------+
|  ПОДВАЛ (Footer):                                                        |
|  - В режиме View:    Кнопка «Закрыть» + Доп. контекстные действия        |
|  - В режиме Edit:    Кнопка «Отмена» (сброс в View) + «Сохранить»        |
|  - В режиме Create:  Кнопка «Отмена» + «Создать запись»                  |
+--------------------------------------------------------------------------+

```

1. **Режим создания (`create`):**
* Все редактируемые поля активны для ввода с плейсхолдерами.
* Системные поля (UUID, `created_at`, `created_by`) скрыты либо помечены плашкой «Генерируется автоматически».
* Подвал: кнопка «Отмена» и акцентная кнопка «Создать».


2. **Режим просмотра (`view`):**
* Открывается по умолчанию при клике на запись из таблицы или карточки.
* Поля отображаются в статичном виде с высокой четкостью текста.
* В шапке доступна контурная кнопка **«Редактировать»** (`Pencil`) — при наличии прав у роли пользователя.
* В верхней части активна **панель быстрых действий** (раздел 4.4).


3. **Режим редактирования (`edit`):**
* Активируется по клику на кнопку «Редактировать» из режима просмотра.
* Разрешенные поля трансформируются в интерактивные инпуты/селекторы.
* Неизменяемые поля остаются заблокированными (раздел 4.3).
* Подвал: кнопка «Отмена» (возвращает данные к состоянию до правок и переключает в режим `view` без закрытия окна) и кнопка «Сохранить изменения» (`Save`).

### 4.3. Регламент неизменяемых полей (Immutable / Readonly Fields)

Поля, которые не подлежат изменению после создания записи (первичные ключи, системные даты, идентификаторы авторов, внешние телефонные номера из Sotka API), подчиняются строгим интерфейсным правилам:

* **Визуальное оформление:**
* Контейнер поля окрашивается в приглушенный матовый тон: `bg-zinc-100/60 dark:bg-zinc-800/40 border-zinc-200/50 dark:border-zinc-700/50`.
* Текст значения: `text-zinc-600 dark:text-zinc-400 font-mono select-all`.
* Поле снабжается бейджем «Только чтение» (`Lock`, `w-3 h-3`) или значком копирования (`Copy`).


* **Интерактивность (Click-to-Copy):**
* Поле **запрещено** для ручного ввода и редактирования (`readOnly={true}`).
* Поле **активно для клика**: курсор мыши меняется на `cursor-pointer`.
* При клике в любую область поля:
1. Значение копируется в буфер обмена (`navigator.clipboard.writeText(...)`).
2. Появляется всплывающая подсказка / тост: «Скопировано в буфер».
3. На мобильных устройствах срабатывает микро-виброотклик `navigator.vibrate(30)`.
4. Иконка `Copy` на 1.5 секунды сменяется на контурную галочку `Check`.

### 4.4. Островок быстрых действий на форме просмотра (Quick Action Island)

В режиме `view` непосредственно под шапкой модального окна размещается плавающий матовый островок быстрых действий (`QuickActionBar`):

* **Для модуля «Лиды»:**
* *Быстрая смена статуса:* Селектор статусов воронки (в 1 клик переводит лид в `Обработан`, `Назначен`, `Подписан` или `Отмена` с автоматическим сохранением без перехода в режим полного редактирования).
* *Связь в 1 клик:* Кнопка вызова GSM (`tel:`), кнопка WhatsApp API (`wa.me`), переход в профиль Instagram.
* *Связывание:* Кнопка «Связать с продавцом» (открывает селектор свободных аккаунтов Sotka).


* **Для модуля «Продавцы»:**
* Кнопка быстрого звонка ответственному лицу.
* Кнопка перехода к списку связанных транзакций/платежей.
* Кнопка закрепления за текущим консультантом (создание `connection`).


* **Для финансовых модулей («Выплаты» / «Начисления»):**
* Кнопка смены финансового статуса (`начислено` → `выплачено`).
* Кнопка выгрузки квитанции/чека.

## 5. Система цветовой индикации и статусов

* **Индикаторы статусов воронки лидов:**
* `Открыт` — неоновый лазурный (`bg-blue-500/15 text-blue-600 dark:text-blue-400 border-blue-500/30`).


* `Обработан` — фиолетовый (`bg-purple-500/15 text-purple-600 dark:text-purple-400 border-purple-500/30`).


* `Назначен` — янтарный / оранжевый (`bg-amber-500/15 text-amber-600 dark:text-amber-400 border-amber-500/30`).


* `Подписан` — изумрудный (`bg-emerald-500/15 text-emerald-600 dark:text-emerald-400 border-emerald-500/30`).


* `Отмена` — приглушенный кораллово-серый (`bg-rose-500/15 text-rose-600 dark:text-rose-400 border-rose-500/30`).




* **Индикаторы сотрудников:**
* Каждому консультанту и SMM-специалисту назначается визуальный цветовой маркер или двухбуквенный круглый аватар с индивидуальной обводкой для визуальной дифференциации в таблицах и карточках.

## 6. Профиль пользователя и персональная аналитика

Раздел открывается по клику на профиль в сайдбаре (ПК) или нижнем баре (смартфон):

* **Карточка сотрудника (Личные данные):**
* ФИО, текущая системная роль (`admin`, `consultant`, `smm`), логин, телефон.


* Интерактивный переключатель темы оформления (`Light` / `Dark` / `System`).


* Кнопка безопасного выхода из сессии (`LogOut`).




* **Островок персональной статистики (KPI Dashboard):**
* Для **SMM**: счетчик созданных лидов за сутки, неделю, месяц; процент отмененных заявок.


* Для **Консультанта**: лиды в работе, закрытые сделки (`Подписан`), начисленная комиссия за подключение и сопровождение за текущий месяц (сом).


* Для **Администратора**: общие сводные показатели воронки, выручка платформы, статус последней синхронизации Sotka API.

## 7. Всплывающие уведомления (Toast) и обработка датасетов DataJournal

* **Позиционирование Toast (`Toast.tsx`):**
  * Для предотвращения перекрытия интерактивных кнопок мобильного нижнего бара (`MobileBottomBar`) контейнер тостов имеет адаптивное позиционирование: `fixed bottom-20 sm:bottom-6 left-1/2 -translate-x-1/2 z-50`.
  * На мобильных устройствах (до 640px) уведомления парят строго над нижним баром навигации, не блокируя переключение вкладок.
  * На десктопе тосты центрируются внизу экрана со стандартным отступом `bottom-6`.

* **Обработка данных и пагинация в `DataJournal`:**
  * Серверные экшены по умолчанию возвращают полный рабочий датасет (`pageSize = 1000`), позволяя компоненту `DataJournal` осуществлять мгновенный клиентский поиск, расширенную фильтрацию по конструктору правил и сортировку без сетевых задержек.
  * Расчет количества страниц (`totalPages`) динамически учитывает активные фильтры: при активном поиске или фильтрах расчет ведется по отфильтрованному массиву `sortedData.length`, а в исходном состоянии — по `totalCount ?? sortedData.length`.

## 8. Модуль «Сотрудники», навигация в профиль и быстрые действия

* **Интерактивная навигация в профиль:**
  * В десктопной шапке (`TopHeader`) мини-аватар профиля рядом с переключателем темы оформлен ссылкой `<Link href="/profile">` с микроанимацией наведения.
  * В десктопном сайдбаре (`DesktopSidebar`) плашка пользователя (как в развернутом, так и в свернутом виде) выполняет роль кликабельного перехода в `/profile`.
  * В боковое меню администратора интегрирован раздел `Сотрудники` (`/employees`) с иконкой `Users`.

* **Модуль «Сотрудники» (`/employees`):**
  * Доступен исключительно роли `admin`.
  * Реализован на базе `DataJournal`: таблица на десктопе, карточки на мобильных устройствах.
  * Карточки оперативной статистики: Всего в штате, Администраторы, Консультанты, SMM-операторы, Заблокированные.
  * Действия: добавление сотрудника через модальное окно (логин, пароль, ФИО, телефон, роль), редактирование параметров, сброс пароля в 1 клик, быстрая блокировка/разблокировка переключателем статуса.

* **Режим глобального администратора в `/profile`:**
  * Администратору доступна панель быстрого выбора любого сотрудника компании.
  * При выборе сотрудника профиль переключается в контекст выбранного пользователя: отображается его персональный KPI-дашборд (показатели SMM или консультанта), возможность редактирования данных и сброса пароля без ввода старого пароля.

* **Связанные лиды и назначение куратора в «Продавцах»:**
  * В таблице продавцов добавлена колонка «Связанный лид» с бейджем статуса воронки и ФИО клиента.
  * В колонке «Куратор» для администратора выведен компактный селектор для мгновенного назначения сотрудника.
  * Назначение куратора автоматически генерирует или обновляет запись в `connections` с расчетом процентной ставки и суммы комиссии.

* **Быстрые действия в «Лидах»:**
  * В колонке «Ответственный» для администратора выведен выпадающий список активных консультантов для мгновенного перераспределения обращений в 1 клик.

## 9. Оптимизация первого кадра (SSR), поведение FAB и сквозные быстрые действия

* **Предотвращение мигания модулей при первом открытии (Role Flash Elimination):**
  * Корневой макет `app/layout.tsx` (серверный компонент) считывает сессионные куки `crm_role`, `crm_user_name`, `crm_user_login` и передает их в `AuthProvider` в качестве `initialRole`, `initialUserName`, `initialUserLogin`.
  * Серверный рендеринг (SSR) генерирует HTML строго с учетом реальной роли пользователя (например, SMM-оператор сразу получает разметку только с разрешенными разделами «Лиды» и «Профиль»).
  * Устранено дефолтное значение роли `'admin'` на сервере, исключен Layout Shift и визуальное появление/исчезновение запрещенных вкладок.

* **Изоляция и скрытие плавающей кнопки FAB (`FAB.tsx`):**
  * Z-index кнопки FAB понижен до `z-30` (под матовыми оверлеями `z-[60]` модальных окон).
  * В `AppLayout` внедрен флаг `hideFab`: при открытии любого модального окна (`EntityModal`, `LeadSellerMappingModal`, `SalesScriptsSheet`, `cancelDialog`) FAB-кнопка полностью исключается из DOM-дерева, гарантируя отсутствие наложения на элементы формы на экранах мобильных устройств.
  * В форме создания лида кнопка отправки формы получила постоянную понятную сигнатуру: `«Сохранить запись»`.

* **Сквозные действия связывания и назначения куратора:**
  * В строках реестра `DataJournal` (как на ПК, так и на смартфонах) для администраторов и консультантов добавлена прямая кнопка `«Связать»` (`Link2`), мгновенно открывающая диалог связывания со свободным продавцом без перехода в карточку.
  * Если лид не был назначен на консультанта, селектор ответственного в таблице подсвечивается акцентным янтарным бейджем `«+ Назначить сотрудника»`.
  * В модальном окне связывания `LeadSellerMappingModal` для администратора выведен селектор сотрудника: назначение консультанта и привязка продавца выполняются в один клик с одновременной фиксацией комиссии в `connections`.
